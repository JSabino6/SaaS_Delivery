CHECKLIST DE CONFIGURAÇÃO DO BOT (VERSÃO ATUAL)
Data: 2026-03-02

Este documento é o meu guia operacional para colocar o bot em funcionamento com segurança.
A ideia é simples: seguir do topo ao fim e validar cada etapa.

=================================================================
1) COMPONENTES QUE EU PRECISO TER RODANDO
=================================================================

1.1 Backend (FastAPI) - pasta API/
- Responsável por webhook, processamento conversacional, pedido, pagamento e cron.
- Entrypoint: API/main.py

1.2 Frontend (Dashboard Streamlit) - pasta Dashboard/
- Painel operacional para restaurante/admin.
- Entrypoint: Dashboard/app.py

1.3 Banco (Supabase / Postgres)
- Tabelas de restaurante, produto, pedido, estado de conversa, entrega, etc.

1.4 Redis (opcional, mas recomendado)
- Buffer/debounce de mensagens
- Deduplicação de webhook
- Rate limit
- Locks distribuídos
- Cache de dados do restaurante

=================================================================
2) VARIÁVEIS DE AMBIENTE ESSENCIAIS
=================================================================

Obrigatórias (mínimo para iniciar):
- SUPABASE_URL
- SUPABASE_KEY
- GROQ_API_KEY
- WEBHOOK_SECRET
- PUBLIC_BASE_URL

Segurança/integrações:
- CRON_SECRET
- MP_WEBHOOK_TOKEN
- CRED_ENCRYPTION_KEY
- CACHE_INVALIDATE_TOKEN

Admin Dashboard:
- ADMIN_USER
- ADMIN_PASS

Recomendadas para estabilidade:
- REDIS_URL
- HTTP_VERIFY_TLS=true
- WEBHOOK_RATE_LIMIT_PER_MIN=60
- MESSAGE_DEBOUNCE_SECONDS=5
- MAX_WEBHOOK_BODY_BYTES=262144
- MAX_INCOMING_TEXT_CHARS=4000
- MAX_BUFFER_TEXT_CHARS=8000
- MAX_QTD_ITEM=10

Parâmetros de rotina:
- CART_ABANDONED_REMINDER_MIN=10
- CART_ABANDONED_CANCEL_MIN=15
- MAX_ABANDONED_SWEEP=200
- STATE_STALE_RESET_MIN=120
- MAX_STATE_RESET_SWEEP=500
- AVALIACAO_DELAY_MIN=30
- MAX_AVALIACAO_SWEEP=200

=================================================================
4) CONFIGURAÇÃO DO WHATSAPP (UAZAPI)
=================================================================

4.1 Para receber mensagens
Configurar webhook no provedor apontando para:
- {PUBLIC_BASE_URL}/webhook?token={WEBHOOK_SECRET}

4.2 Para enviar mensagens
Cada restaurante precisa ter no banco:
- instance_token
- instance_name
- phone_id

Sem esses três campos corretos, o envio falha.

=================================================================
5) CONFIGURAÇÃO DE PIX (MERCADO PAGO)
=================================================================

5.1 Pré-requisito
- Token de acesso do MP por restaurante.

5.2 Como eu configuro
- Cadastro o token no Dashboard.
- O painel criptografa e salva em mp_access_token_enc.
- Backend e Dashboard devem usar a mesma CRED_ENCRYPTION_KEY.

5.3 Webhook do Mercado Pago
- Endpoint no backend: /webhook/mercadopago
- Validar MP_WEBHOOK_TOKEN nas chamadas.

=================================================================
6) ENDPOINTS QUE PRECISAM ESTAR ACESSÍVEIS
=================================================================

API principal:
- POST /webhook
- POST /webhook/mercadopago
- GET  /payments/qr/{payment_id}.png
- GET  /health

Admin/API utilitário:
- POST /admin/cache/invalidate
- POST /admin/chat/toggle_pause

Crons:
- GET /cron/abandoned-carts
- GET /cron/reset-states
- GET /cron/avaliar

=================================================================
7) AGENDAMENTO DE CRON (OBRIGATÓRIO EM PRODUÇÃO)
=================================================================

Todos os endpoints /cron devem ser chamados com token (query ou header).

Sugestão prática de frequência:
- /cron/abandoned-carts -> a cada 2 a 5 minutos
- /cron/reset-states -> a cada 10 a 30 minutos
- /cron/avaliar -> a cada 10 minutos

=================================================================
8) EXECUÇÃO DO PROJETO
=================================================================

8.1 Docker (recomendado)
- docker-compose up --build -d

8.2 Local manual
Backend:
- cd API
- pip install -r requirements.txt
- uvicorn main:app --reload --host 0.0.0.0 --port 8000

Dashboard:
- cd Dashboard
- pip install -r requirements.txt
- streamlit run app.py

=================================================================
10) ERROS COMUNS QUE EU EVITO
=================================================================

- WEBHOOK_SECRET diferente entre provedor e API.
- PUBLIC_BASE_URL com barra no final ou URL não pública.
- CRED_ENCRYPTION_KEY diferente entre API e Dashboard.
- instance_token vazio no restaurante.
- REDIS_URL inválida (causa perda de robustez no fluxo concorrente).
- SQL de migração não aplicado (campos faltando no banco).
